逐字段披露试用

1. 首次启动后导入 field-a.csv。它包含比例、金额和分组三列。选择内侧与外侧连接。普通双域路线可用获准的 Codex MCP 宿主与已准入 Qoder；在企业 Agent 模式下，输入需要单独授权，宿主需要保持连接并处理任务。使用真实账户前先明确本次账户、数据范围和费用上限。无账户可先走本地规则体验，记录完成到哪步。
2. 输入“只计算 trial_amount_x 的总和”，在提案前只选 trial_amount_x。保留行值与结果行授权的默认关闭状态，核对内侧接收方，再准备公开任务。内侧会收到任务原文、获准字段名和类型。单独勾选样例时，还需指定字段和行号。在下一步的公开批准页核对对外符号、用途、目的地与实际 JSON，外侧应只见一个整数字段和独立生成的合成样例。
3. 批准后取得程序，完成公开样例检查与本机执行。第一份输入的金额合计为 13。导入只含 trial_amount_x 的 field-b.csv，选择刚才的任务并复用原程序；合计应为 6，程序摘要相同。结果界面会区分执行成功和独立正确性评估。
4. 退出并重开，在历史协作任务中找回原任务与复用结果。若交付状态未知，请先刷新或查询原任务。记录是否需要别人代操作、谁能看到哪些材料、程序在哪儿运行、是否有下一次会用到的任务。

候选内的入口与证据

• Codex MCP 内侧 + Qoder SDK 外侧：常规入口有早期本机真实合成记录；本候选的独立双域试用待反馈。
• 自定义 HTTP：四协议有本地模拟响应记录。真实端点需要单独的供应商账户与验收。
• 外侧 Codex、OpenCode、Claude Code：已有本机客户端配模拟响应的记录。
• Cursor：专项 SDK 源码路线有真实合成记录；桌面列表中的原生 CLI 生成仍受限。
• Antigravity：有桌面生成后手工导入的合成记录，原生 ACP 握手与自动生成分别计。
• 远程节点：有本机分进程的断线取回、公开修复及复用记录，实际跨机连接待验。
